# MiniLang 程序执行可视化调试器

在已有的 MiniLang 语言执行内核（词法/语法分析 + 全量执行事件流）之上，接通了
可实际单步、断点、查看变量的调试会话与页面。

## 运行

```bash
# 后端（Starlette + uvicorn，仅使用标准库持久化会话）
python -m backend.server --port 8001

# 前端（开发服务器，/api 自动代理到 8001）
cd frontend && npm install && npm run dev
```

打开 http://localhost:5173 ，从示例中选择「递归 / 循环 / 运行错误」程序。

## 调试能力

- 单步进入 / 单步越过 / 跳出函数 / 继续到下一断点。
- 在行号旁的圆圈点击设置断点；只有真正可执行的行接受断点，其他行会被明确拒绝，
  不会悄悄移动到相邻行。
- 暂停时可以随时增删断点后再继续。
- 调用栈面板可切换栈帧；变量面板始终显示**当前所选栈帧**的局部变量，递归中各层
  同名变量互不混淆；每次暂停/继续后变量与高亮行都以新事件为准，不残留旧暂停位置。
- 「保存会话」把光标位置、断点、调用链与输出落盘；关闭页面甚至重启服务后，可从
  「已保存会话」重新打开，暂停的会话能继续执行。
- 程序因错误退出后，最后一次错误信息、出错行和完整调用链（含每层局部变量）
  仍然保留、可保存、可重开查看；结束后的单步/继续会被明确拒绝。
- 编辑新源程序时不会复用旧会话的行号断点：新会话从空断点集开始；编译检查会列出
  属于其他源程序的旧会话，旧会话仍以其自身源代码独立保存。

## 测试

```bash
python -m pytest backend/tests -q     # 13 个后端测试
cd frontend && npx vitest run         # 栈帧变量派生逻辑测试
npx tsc --noEmit && npx vite build     # 类型检查与构建
```

后端测试用进程内 ASGI 调用覆盖完整 HTTP 流程（暂停 → 保存 → 用全新 store 重开 →
继续 → 结束），以及递归同名变量、循环 step-over、运行错误调用链持久化、
源程序变化后的旧会话处理。
